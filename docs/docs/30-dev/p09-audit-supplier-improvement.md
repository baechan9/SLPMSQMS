# P9 심사·인증·협력사 실적·개선 과제

공용 심사 엔진(내부·협력사·고객·인증 기관, Vol.6c IAU), 고객 심사 대응과 VDA 6.3 계산기(CAU), 사업장 인증(CER), 협력사 심사(SAU)·품질 목표·스코어카드·등급(SQM), 개선 과제(IMP)를 만든다. 바인딩 IMPROVEMENT가 실제 구현으로 바뀐다. PoC 시나리오 S4(VDA 6.3)가 여기서 완성된다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 질문지·등급 규칙 → 심사 생성(질문 스냅숏) → 모바일 수행·점수 → 보고서 → 지적·시정·검증, 고객 심사 준비·자체 평가·VDA 6.3 결과, 협력사 심사·스코어카드·등급 반영, 개선 과제 게이트가 동작 |
| 기간(4명 기준) | 누적 240영업일(P8 이후 약 47일 — 심사 엔진 사슬이 길어 이 페이즈가 가장 김) |
| 마일스톤 | S4 VDA 6.3 BMW 공정 심사 대비 |
| 착수 조건 | P4 DVQ-007(게이트웨이), P3 MTG-001(CER-002), P6 IQC-007 계약(SQM-002) |
| 다음 페이즈로 당겨 착수 가능 | P10 중 GAU-001, LMS-001, TRN-001, LAB-001(선행이 앞 페이즈뿐) |

## 3. 레인별 작업

IAU-002 → 003 → 004는 P12 AIQ-002의 선행으로, 임계 경로 다음으로 긴 사슬이다(여유 약 7 M/D). 레인 A를 가장 먼저 착수하고, P8 게이트를 기다리지 말고 IAU-001부터 당겨 시작한다.

### 레인 A — 심사 엔진(IAU-001 → 002 → 003 → 004·005·006 → 007)

1. **IAU-001**: `QMS_AuditChecklist__c`·`QMS_AuditQuestion__c`, 등급 구간·강등 규칙 객체(`QMS_AuditGradeRule__c`), 점수 계산기 등록 메타데이터, 편집기·CSV 일괄 등록·규칙 시뮬레이터. 질문 원문은 라이선스 확인 전 SL 자체 문구만(D6C-2, TextSource·LicenseConfirmed). 데모 보강: GradeRule ExternalKey, 등급 값은 데모 가정(A ≥ 90, B ≥ 80, C < 80, 별표 0점 → C)이며 품질경영팀 검수 필요(D6C-3).
2. **IAU-002**: `QMS_Audit__c`(RecordType INTERNAL·SUPPLIER·CUSTOMER·CERTIFICATION)·심사팀·결과 라인, 생성 서비스(질문 스냅숏), 상태 전이, 통보, 심사원 자격 게이트웨이(AUDITOR_QUALIFICATION — P10 TRN-004 전에는 기본 구현 "항상 true + WARN", D6C-11), 독립성 검사, 심사 캘린더, `QMS_AuditEvent__e`. 데모 보강: ResultItem·CustomerAuditPrepTask ExternalKey.
3. **IAU-003**: 수행 화면(모바일), 답 입력 규칙, 점수 계산 서비스와 일반 계산기(COMPLIANCE, POINTS, PRODUCT_AUDIT), 공통 등급 평가기, 보고서 상신·결재·PDF.
4. **IAU-004**: `QMS_AuditFinding__c`·`QMS_AuditFindingAction__c`, 기한 규칙(D6C-9), 시정 계획·검토·실행·검증·종결, 반복 지적, 기한 경과 알림, `QMS_AuditFindingHitRule`(AI 적중 — 추천은 P12), 후속 연계(게이트웨이), `QMS_AuditFindingEvent__e`. 고객이 8D 양식을 요구한 지적만 EIGHT_D(AUDIT_FINDING, D6C-4).
5. **IAU-005**: 등록 증빙 쿼리 메타데이터, `QMS_AuditEvidenceRule__c`, 증빙 제공자 인터페이스, 실시간 조회 서비스(자유 SOQL 금지, D6C-5), 증빙 패널·제시 모드, 스냅숏, 증빙 패키지 PDF, 초기 규칙 세트. 제공자 EV-TRAINING(P10 TRN-004)·EV-GAUGE-CAL(P10 GAU-004)은 나중에 등록된다.
6. **IAU-006**: 연간 프로그램(`QMS_AuditProgram__c`), 위험 점수·빈도, 생성 마법사, 커버리지, 결재·개정, 월 배치 심사 생성, 보드.
7. **IAU-007**(SNOW·SF): 복제 대상 등록, KPI 정의 등록(P7 레지스트리, RAG는 D7-1 방식으로 통합), 분석 쿼리 키. Snowflake 뷰는 외부 트랙.

### 레인 B — 고객 심사·인증(CAU-001, CAU-002 → CAU-003, CER-001 → CER-002)

1. **CAU-001**(IAU-002·005 뒤): 고객 심사 고유 필드, `QMS_CustomerAuditPrepTask__c`·템플릿, 자동 과제 생성, 이전 고객 지적 확인 과제, 자체 평가 생성, D-day 알림, 고객 심사 콕핏. review-pack 3절 1건.
2. **CAU-002**(IAU-001·003 뒤): VDA 6.3 계산기(Scheme VDA63, 설정 데이터 기반 — 코드에 규칙 숫자 없음), P6 질문 공정 단계별 복제, 집계 방식 설정(TotalMethod, StepAggregation), 결과 매트릭스, 자체 평가 대 고객 결과 비교, **골든 케이스 테스트**.
3. **CAU-003**: 고객 공식 결과, 고객 지적 필드, 회신서 PDF·제출 기록, 수용 여부, 8D 연결(게이트웨이), 재심사·등급 조치, 고객별 이력 화면.
4. **CER-001**: `QMS_Certification__c`, 심사 주기·계획 To-Do, 만료 알림, 준비도 점검, 인증 현황 보드.
5. **CER-002**: 인증 기관 지적 기한·제출 패키지, 인증 위험 표시, 경영검토 입력 자료 정의·생성·회의(MTG-001) 연결.

### 레인 C — 협력사(SAU-001 → 002 → 003, SQM-001 → 002 → 003, INT-019)

1. **SAU-001**: 등급별 심사 주기(D6C-7), 도래 알림, 계획 화면, 잠재력 평가·지도/진단, 위험 신호 기반 특별 심사 제안, 심사 요청 서비스.
2. **SAU-002**: 협력사 공유·공개 규칙, `QMS_AuditFindingResponse__c`, 포털 화면(심사 목록·준비 자료·시정 계획·완료 보고), SQE 검토, 기한 경과.
3. **SAU-003**(IAU-007 뒤): 최근 결과 조회 서비스, 후속 심사 규칙, 협력사 심사 요약 화면. Snowflake 최근 결과 뷰는 외부 트랙.
4. **SQM-001**: `QMS_SupplierTargetSet__c`·Target, 연간 수립(전년 복사·일괄 개선율), 결재, 포털 협력사 합의.
5. **SQM-002**(SNOW·SF·MULE, SAU-003 뒤): 지표·등급 구간 메타데이터(D6C-6), `QMS_SupplierScorecard__c`와 적재 수신, 스코어카드 화면, 조회 서비스. 점수·등급 계산은 외부 트랙. review-pack 3절 1건.
6. **SQM-003**(IMP-002 뒤): 등급 확정 화면, 등급 반영 서비스(유일 경로 → `Account.SupplierGrade__c`, `QMS_SupplierGradeEvent__e`), 등급별 후속 조치(D6C-8), `QMS_SupplierImprovementPlan__c` 포털 흐름, 포털 스코어카드.
7. **INT-019**(Salesforce 쪽): 신규 부품 PPAP 요청 수신 핸들러(QMS-09-INT-002 기반 클래스), PPAP 이벤트 → 부품개발시스템 전달 계약.

### 레인 D — 개선 과제(IMP-001 → IMP-002)

1. **IMP-001**: `QMS_ImprovementProject__c`·단계·팀, 방법론 템플릿(DMAIC 기본 + 사용자 마일스톤, D6C-10), `QMS_ImprovementService.createFromSource`(멱등), 등록·게이트·일정 변경·종결 결재, 지연 알림, 이벤트, 과제 화면.
2. **IMP-002**: 바인딩 IMPROVEMENT 구현, KPI 월 실적 객체·자동 적재·수동 입력, 기준값 제안, 효과 판정, KPI 차트(P7 공용 컴포넌트), 포트폴리오, 개선 KPI.
