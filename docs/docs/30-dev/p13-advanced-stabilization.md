# P13 고도화·통합 안정화

W3 고도화 WI(AI 추천 2종, 이상 성적서 탐지, 선택 연계 3종)와 화면별 사용 가이드(UX-002)를 만들고, 전 시나리오 회귀·성능·보안 점검을 거쳐 SIT(Partial Copy Sandbox) 이관을 준비한다. 조건부 WI는 결정 결과에 따라 착수하거나 폐기한다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | 남은 WI 완료(또는 결정에 따른 폐기), 새 Scratch Org에서 S0~S13 전 시나리오 재현, SIT 배포 준비 |
| 기간(기본 인원) | 누적 269영업일(P12 이후 약 3일 + 안정화 작업). QMS 4명·PMS 3명 시뮬레이션(2026-11-06, [개발 플랜](dev-plan.md) 9.2절) |
| 마일스톤 | 전 시나리오 회귀, SIT 이관 준비 |
| 착수 조건 | WI별 선행. INT-021은 D-1·D9-6, INT-009·013은 D9-7 결정 |

## 3. 레인별 작업

### 레인 A — W3 AI·탐지(AIQ-014, AIQ-015, IQC-008)

1. **AIQ-014**: 4M 변경 기반 필요 시험 추천(과거 4M ↔ 시험 이력, 불량 유형 → 시험 분류 매핑), 4M 화면(P6 4MC-003 AI 자리)에 실행 컴포넌트 배치, 적중 판정 설정.
2. **AIQ-015**: 고객 심사 대비 예상 지적 추천(질문별 위험 뷰), 고객 심사 화면(P9 CAU-001) 실행 컴포넌트.
3. **IQC-008**: 이상 성적서 탐지(Snowflake 규칙) → 알람 → AI-004 기록 → SQE To-Do, 제외 시 재알림 억제. S9 엡실론 성적서 값 동일 사례가 대상이다.

### 레인 B — 선택·조건부 연계(INT-009, INT-013, INT-021)

| WI | 착수 조건 | Salesforce 쪽 |
| --- | --- | --- |
| INT-009 클레임 봉쇄 의심 재고 SAP 보류 | D9-7에서 SL 요청 시 | `QMS_ClaimEvent__e` CONTAINMENT_STARTED 계약, 결과 코멘트·알림 회신 |
| INT-013 4M 적용 허가 → MES 통보 | D9-7에서 SL 요청 시 | `QMS_FourMEvent__e` 계약, 결과 회신 |
| INT-021 PMS 별도 Org 디지털 스레드 | D-1이 "별도 Org"일 때만(단일 Org면 폐기, D9-6) | LELE REST·이벤트 계약, 기준정보 외부 키 변환, 사번 매칭 |

### 레인 C — 사용 가이드(UX-002)

화면별 가이드(레코드 페이지 가이드 아이콘, 사용자 언어, 없으면 en_US). 모든 화면이 나온 뒤라 마지막에 둔다. 가이드 문서는 화면을 만든 WI의 완료 보고서와 데모 시나리오 단계를 원천으로 쓴다.

## 5. Scratch Org 준비

새 기능 설정은 없다. T13-1은 반드시 새 Org로 한다. 3일 이상 걸리면 회귀 중에 Org가 만료되지 않게 30일 Org를 새로 만든다.

## 6. 데모 데이터

전체 적재(P10 이후와 같음). 데모 기준일과 회귀 날짜가 다르면 생성기 `--today`로 회귀 날짜 기준 데이터·기대값을 다시 만든다(dev-plan 11절).
