# P18 PMS 대시보드·보고·분석

역할별 PMS 대시보드, PMO 전체 프로젝트 보드, 공장·차종 양식 주간 보고, 의사결정사항을 만들고, Snowflake 기반 분석(자원 부하·비용 분석·요구사항 충족·디지털 스레드)을 붙인다. 이 페이즈의 W1 4건이 끝나면 **PMS 1차 오픈 범위**가 완성된다. 명세는 [Vol.P5](../10-workitems/volp5-pms10-11-dashboard-ai.md)·[Vol.P1](../10-workitems/volp1-pms02-03-project-resource.md)·[Vol.P3](../10-workitems/volp3-pms05-06-cost-deliverable.md)이다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목표 | SL PMS 홈 역할별 템플릿 7종, PMO 보드(QCD, Q 상태 판정), 일간·주간 보고(스냅숏 발행·정정 재발행, 비용 권한 분리), 의사결정사항(조치 항목·To-Do), 자원 부하(Snowflake), 비용 대시보드·Excel 왕복, 요구사항 충족률·디지털 스레드 |

| 마일스톤 | **PMS 1차 오픈 범위 완성**(PoC 시나리오 4 — 공장별 권한 분리와 주간 보고) |
| 착수 조건 | 기반 P3 대시보드 공용 라이브러리(QMS-07-DSH-001~004, 2026-11-06 P7에서 당김), P16 WBS-007·EFF-002·CST-002·003, P17 RSK-001·ISS-001·GAT-001 |

## 3. 레인별 작업

### 레인 A — 대시보드·보고(DSH-001 → 002 → 003, DSH-004)

1. **DSH-001**: PMS 일별 스냅숏·KPI 뷰(Snowflake 외부 트랙 부분 포함), KPI 레지스트리 등록(`QMS_KpiDefinition__mdt`에 PMS 키 — DP5-1 QMS 이름 그대로 재사용), 위젯 36종 등록(공용 컴포넌트 설정), 전용 위젯 3종(프로젝트 QCD 카드·WP 진척·마일스톤 타임라인), 페르소나 규칙(MDT는 가정 역할 — DP5-11), 템플릿 7종, 홈 보드.
2. **DSH-002**: PMO 보드(공장·고객·차종·연도·SOP 필터), Q 상태 판정(DP5-4, `QualityRag*` 필드 3개), 비용 표시는 FLS + `PMS_ViewCost`만(DP5-3 — KPI 값·PDF·AI 답변에 비용 금지).
3. **DSH-003**: 보고 템플릿 → 스냅숏 → 발행 → 정정 재발행(DP5-5), `PMS_WeeklyReportLine__c`, 공장 격리, 비용 권한.
4. **DSH-004**(W2 → W1, DP5-6): 의사결정사항, 후속 조치는 `CMN_ActionItem__c`·To-Do. MTG-001 조치 항목 `SourceObject`·상태 훅(Vol.0 변경 요청).

### 레인 B — 분석(EFF-003, CST-004, SOR-002 → DLV-003)

1. **EFF-003**(W2): 자원 부하·여유율(Snowflake `MART.V_PMS_RESOURCE_WEEKLY`, KPI), 인원 과부하 알림 `PMS_RES_OVERLOAD`(P19 AIP-003은 인원 경보를 하지 않음).
2. **CST-004**(W2): 비용 대시보드(같은 환율 환산 — Snowflake, D-P5), Excel 가져오기·내보내기(`cmnSheetJs` 정적 리소스 — 먼저 구현하는 WI가 만든다, V0-9), CostRag(DP3-6).
3. **SOR-002**(W2): 요구사항 ↔ 산출물·시험·승인 연결(`PMS_RequirementLink__c` 원본 — DP3-13), 충족률(모든 연결 VERIFIED — DP1-10).
4. **DLV-003**(W2): 입력/출력 추적성 그래프(Snowflake 계보 쿼리, PoC 시나리오 3 데이터 모델).
