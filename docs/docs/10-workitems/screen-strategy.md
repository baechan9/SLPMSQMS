- 공통 화면 부품은 Vol.0 `CMN-00-UX-004`~`009` WI로 상세화했다(`vol0-cmn-common.md` 8절).
- WI별 화면 유형(T1~T8)은 `docs/30-dev/screen-map.csv`의 `화면유형` 열에 있다.
- 개발 규칙(스타일·LWC)은 저장소 루트 `.claude/rules/sf-dev.md` 6절에 반영했다.

## 1. 요약

**결론: 표준 Lightning 구조는 그대로 쓴다. 그 위에 "품질 업무 작업공간" 표준을 하나 정해 모든 메뉴가 같은 모양으로 동작하게 한다.** 화면을 메뉴마다 새로 설계하지 않는다. 8가지 화면 유형과 1개의 레코드 페이지 표준으로 QMS 45개 요구를 덮는다.

세 가지 축으로 정리했다.

- **사용자를 두 계층으로 나눈다.**
  - 품질 엔지니어·SQE처럼 하루 종일 QMS를 쓰는 전문가는 **품질 업무 앱**(`SL QMS 품질 업무`: 자주 쓰는 업무 탭, 분할 보기 리스트뷰)을 쓴다.
  - 대책 입력·결재만 하는 개발·생산·구매 참여자와 경영진은 **표준 앱의 단순 화면**(`SL QMS`)을 쓴다.
  - 독일 자동차 CAQ(Babtec)가 전문가용 클라이언트와 전 직원용 경량 웹 UI를 따로 두는 것과 같은 판단이다.
  - 콘솔 앱은 쓰지 않는다(DS-7 결정, 2026-11-05: Lightning Console 추가 라이선스 미사용). 모든 앱은 표준 내비게이션이고, 여러 건을 오가는 작업은 분할 보기 리스트뷰와 브라우저 새 탭으로 한다.
- **업무 레코드는 "단계 중심"으로 보여준다.**
  - NCR·4M·8D·Re-PPAP 모두 같은 배치를 쓴다: 상단 진행 단계, 가운데 지금 단계에서 할 일, 오른쪽 결정 지원 레일(AI 추천·결재·코멘트)이다.
  - 지금 단계와 무관한 필드·버튼은 Dynamic Forms·Dynamic Actions로 숨긴다. 숨김 규칙과 서버 검증은 표 하나에서 함께 만든다.
- **표·현장·분석은 표준 화면으로 억지로 풀지 않는다.**
  - 검사 결과·DVP 라인·체크리스트는 전용 그리드, 현장 검사는 태블릿 입력 셸, SPC·추세는 Snowflake 위젯과 드릴다운으로 처리한다.
  - 이 영역은 Salesforce 네이티브 QMS(ComplianceQuest 등)가 약하고 자동차 전문 CAQ(Siemens Opcenter Quality, Babtec)가 강하다. SL 제안의 차별점이 된다.

**반영 결과**

- 공통 화면 WI 6개(UX-004~009, 35 M/D)를 Vol.0에 추가했다. 원안은 37 M/D였다. 체크리스트 엔진의 질문지·점수 계산은 Vol.6c에 이미 명세돼 있어 수행 화면 부품으로 줄였다.
- Vol.2 공수는 5 M/D 줄었다(DVQ-004 7→4, DVQ-007 7→5).
- 나머지 메뉴의 그리드·입력·체크리스트 화면 16건은 각 화면 묶음(A1~A6)을 시작할 때 공통 부품으로 바꾼다(8.1절).

**벤치마크에서 얻은 결론 세 가지**

1. **표준 레코드 페이지를 지킨다.** Salesforce 네이티브 QMS의 강점(설정 용이성, 업그레이드 안정성, CRM과 같은 사용감)은 표준 레코드 페이지를 지킬 때만 유지된다. 그래서 커스텀 LWC는 "표준 페이지 안에 끼우는 부품"으로만 만든다.
2. **차별 포인트는 네 가지다.** 자동차 CAQ가 앞서는 지점은 특성·검사·SPC 중심 화면, 태블릿 현장 입력, 8D 단계 안내, 데이터로 만드는 고객 보고서다. 이 네 가지를 SL 화면 전략의 차별 포인트로 잡는다.
3. **참여 부서용 화면은 가볍게 만든다.** 두 부류 모두 이 필요를 인정한다. QMS 사용자 다수는 대책 입력·결재·조회만 하는 사람이다.

**에이전트 규칙**
- 커스텀 LWC는 하드코딩 색·폰트 대신 SLDS 전역 스타일링 훅과 표준 base component를 쓴다. SLDS 2 전환 때 깨지는 화면을 막기 위해서다.

## 4. 화면 전략 원칙

1. **표준 우선, 끼워 넣기만 커스텀.**
   - 레코드 페이지·리스트뷰·리포트는 표준을 쓰고, LWC는 그 안의 한 영역만 맡는다.
   - 전체 화면을 하나의 커스텀 LWC로 덮는 "SPA형 화면"은 만들지 않는다. 예외는 협력사 포털과 현장 입력 셸(T3)이다.
   - 근거: 정기 릴리즈 대응(RFP 비기능 요구), 현업 설정 변경, SLDS 2 전환.
2. **사람 기준 두 계층.**
   - 전문가(품질 엔지니어, SQE, 품질팀장, 시험·측정·심사 담당)는 업무 앱에서 여러 건을 동시에 처리한다.
   - 참여자(개발·생산·구매·경영진)는 표준 앱에서 "내 할 일 1건"만 처리한다.
   - 같은 레코드라도 참여자 화면은 UX-005 규칙(권한 조건)으로 필드를 줄인다.
3. **단계 중심 레코드.**
   - 상태가 있는 업무 객체는 모두 같은 표준(5절)을 쓴다: 상단 진행 단계, 가운데 현재 단계 입력, 오른쪽 결정 지원 레일이다.
   - 사용자는 "지금 무엇을 해야 하는가"를 스크롤 없이 첫 화면에서 본다.
4. **상태가 화면을 결정한다.**
   - 필드 노출(Dynamic Forms)과 버튼(Dynamic Actions)은 상태·권한 매트릭스 하나(`CMN_UiRule__mdt`)로 관리한다.
   - 같은 매트릭스가 서버 검증(`CMN_UiRuleService`)도 만든다. 객체별로 Flow·Validation에 흩어 쓰지 않는다(UX-005).
5. **표는 그리드, 현장은 태블릿, 분석은 위젯.**
   - 행이 10개를 넘거나 셀 단위 입력이 필요한 데이터는 공통 편집 그리드(UX-006)를 쓴다.
   - 측정·외관 검사는 현장 입력 셸(UX-008)을 쓴다.
   - 추세·통계는 Snowflake 기반 위젯과 드릴다운으로 보여준다.
6. **문맥 안의 분석.**
   - 대시보드로 이동하지 않아도 업무 레코드 안에서 관련 데이터를 본다. 예: NCR 화면에서는 해당 특성의 최근 관리도와 같은 불량의 지난 3개월 발생 건수를, 4M 화면에서는 해당 품번의 최근 Cpk를 본다.
   - 결정 지원 레일의 문맥 분석 패널이 DSH-001 위젯을 레코드 값으로 묶어 보여준다(UX-004 BR-7).
7. **AI는 오른쪽, 결정은 사람.**
   - AI 추천은 항상 레일의 카드(채택/제외 버튼)로 보이고, 대화형 질문은 Agentforce 패널로 한다.
   - AI가 본문 필드를 직접 채우지 않는다(Vol.0 AI-004).
8. **보고서는 데이터에서 만든다.**
   - 8D, DVP&R, PSW, 감사 보고서는 입력된 데이터로 생성한다. 양식에 다시 옮겨 적는 화면을 만들지 않는다(벤치마크: Opcenter·CAQ.Net의 자동 8D).
9. **이미 만든 것을 표준으로 흡수한다(보강).**
   - 구현 완료된 공통 화면을 바꾸지 않고 표준의 부품으로 쓴다. 대상은 진행 단계 `cmnStatusPath`, 코멘트 `cmnCommentTimeline`, 결재 `cmnApprovalLine`, 문서 `cmnDocumentPanel`, 홈 `cmnTodoList`·`cmnWidgetBoard`, 메뉴 허브 `cmnAppMenuHub`, 바코드·사진 `cmnBarcodeScanner`·`cmnPhotoCapture`다.
   - 원안의 새 이름(`cmnMenuHub`, `CMN_MenuItem__mdt`, `QMS_MenuItem__mdt`)은 배포된 이름으로 대체한다.
10. **라이선스·베타 기능에 기대지 않는다(보강).**
    - 콘솔 전용 기능, 베타 기능, 추가 라이선스가 필요한 기능 없이도 모든 화면이 동작해야 한다.
    - 그런 기능은 켜지면 더 좋아지는 선택 사항으로만 쓴다.

## 5. 표준 업무 레코드 화면

상태가 있는 모든 업무 객체(NCR, 4M, Claim·8D, Re-PPAP, 인정시험 계획, 개선과제, 심사, 수평전개, 초기유동, 안정화 계획)는 이 배치를 쓴다. Lightning App Builder의 "헤더, 하위 헤더, 오른쪽 사이드바" 표준 템플릿에 영역을 맞춘 것이라 표준 페이지 편집기에서 그대로 수정할 수 있다.

├────────────────────────────────────────────────┬─────────────────────────┤

AI 화면(QMS-08)은 별도 유형이 아니라 T1의 레일 패널(AI 추천 카드)과 Agentforce 패널로 들어간다. `screen-map.csv`에서는 `AI 패널`로 표기한다.

**유형별 핵심 규칙**

- **T1**
  - 상태 전이는 버튼과 결재로만 한다. 화면에서 상태 필드를 직접 편집하지 않는다(Vol.2 DVQ-003 BR-1과 같은 원칙).
  - 버튼 노출과 서버 허용은 같은 규칙(UX-005)에서 나온다.
- **T2**
  - 행 60개까지 2초 이내에 로드한다.
  - 엑셀 범위 붙여넣기는 미리보기 대화상자로 한다.
  - 셀 검증 오류는 행 단위로 강조한다.
  - 저장은 일괄로 하고, 하나라도 오류가 있으면 전부 저장하지 않는다.
- **T3**
  - 한 화면에 한 시료·한 특성씩 크게 보여주는 "순차 모드"와 표 전체를 보는 "표 모드"를 전환할 수 있다.
  - 통신이 끊겨도 입력이 사라지지 않도록 브라우저에 임시 저장한다(DS-5).
  - 판정 규칙은 업무 WI가 갖고, 셸은 미리보기만 한다.
- **T4**
  - 점수 체계·등급 구간·강등 규칙은 질문지 데이터가 정의한다(Vol.6c IAU-001, CAU-002). 셸은 계산하지 않는다.
  - VDA 6.3 등급 기본값(달성률 90% 이상 A, 80~90% B, 80% 미만 C와 강등 규칙)은 질문지 설정 데이터로 넣는다.
  - 질문지 원문은 라이선스 범위 안에서만 탑재한다(DS-6, Vol.6c D6C-2).
- **T5**
  - 위젯은 Snowflake를 직접 호출하지 않는다(Vol.0 DSH-001 BR-5).
  - 점을 클릭하면 해당 기간·조건의 업무 레코드 리스트로 이동한다.
- **T6**
  - 버전 관리 대상(질문지, 시험 기준)은 ACTIVE 버전을 고치지 않고 새 버전을 만든다.
- **T7**
  - 포털은 SLDS 2 지원이 확인되지 않았으므로 사내 화면과 별도로 디자인 검수한다.
  - 협력사에게 사내 필드명·내부 코드를 보이지 않는다.
- **T8**
  - 홈 첫 화면 To-Do 3초 이내(TDO-004).
  - 메뉴 허브 미결 배지는 To-Do 집계 쿼리 2회 이하(UX-007).

**메뉴 허브(`cmnAppMenuHub`, 앱 페이지, A0에서 골격 구현)**

- **전체 메뉴 모드:** 앱에 속한 메뉴 그룹을 모두 보여준다. 그룹은 개발 품질 / 부품·협력사 품질 / 제품·공정 품질 / 고객 품질 / 품질 운영 지원 / Dashboard / AI / 연계 / 공통 업무 / 기준정보다. 각 기능 타일에는 "내 미결 건수" 배지를 단다.
- **권한 필터:**
  - 권한이 없는 화면은 타일 자체를 숨긴다. 객체 타일은 객체 읽기 권한, 페이지 타일은 Custom Permission으로 판단한다.
  - 보이는 타일이 없는 그룹도 숨긴다.
- **설정:**
  - 메뉴 구성은 `CMN_AppMenu__mdt`·`CMN_AppMenuItem__mdt`(배포됨)로 관리한다. UX-007에서 앱·권한·배지·검색어 필드를 더한다.
  - 메뉴별 허브 페이지(QMS_Menu02~09 등)는 내비게이션에서 빼고 그룹 머리글의 "메뉴 열기"로 연다.
- **상단 검색창:** 화면 이름 검색과 업무 번호 바로가기를 함께 한다. 예: `NCR-KR01-2027-000123`을 입력하면 그 레코드로 이동한다. 번호 접두어 → 객체 대응은 채번 규칙(`CMN_NumberingRule__mdt`)에서 읽는다.

**여러 건 처리 규칙(표준 내비게이션, 콘솔 미사용)**
- 작업 대기열은 리스트뷰를 분할 보기로 열어 목록과 레코드를 나란히 둔다. 품질 엔지니어가 NCR 여러 건을 오가며 처리하는 패턴에 맞춘 것이다.
- 하위 레코드(라인·결재 요청·문서)는 페이지를 옮기지 않고 레코드 페이지 안(관련 탭, 모달, 결정 지원 레일)에서 처리한다.
- 다른 레코드를 동시에 볼 때는 브라우저 새 탭으로 연다. 화면은 탭 간 상태 공유를 전제로 하지 않는다.
- 자주 여는 레코드·리스트뷰는 사용자가 내비게이션 바 개인화로 고정한다.
