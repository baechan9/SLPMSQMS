## 2. 구현 내역

- **Apex** `CMN_DocumentCompareController`:
  - compare(이전, 이후):
    - 사용자 권한으로 두 리비전을 읽고, 같은 문서의 서로 다른 리비전인지 확인한다.
    - 확장자로 텍스트 없는 형식(스캔 이미지·CAD)이면 비교 불가를 돌려준다(AI 호출 0회).
    - 그 밖에는 목 응답을 DTO로 바꾼다: 구분 라벨·위치·이전·이후, 행 키 라벨·셀.
  - applySummary는 A단계 자리 구현이다.
- **LWC** `cmnDocumentCompare`(LightningModal):
  - 이전·이후 리비전 선택(기본: 바로 전 → 최신).
  - 결과: 변경 요약(고칠 수 있는 입력란, "AI 생성"·예시 데이터 배지), 변경 목록 표, 표 비교(행 키 = 특성 번호).
  - 상태: 비교 불가·준비 중, 같은 리비전 선택 오류.
  - 버튼: 반영, 닫기.
- **문서 패널** `cmnDocumentPanel`(DOC-001 컴포넌트): 리비전이 둘 이상인 문서에 "버전 비교" 버튼을 더하고 대화상자를 연다. 기존 동작은 바꾸지 않았다.
- **목 응답:** `data/demo/mocks/dwh/CMN_DOC_COMPARE/{ok,no-text}.json`(예시 문구, 특성 3개 규격 변경).
- **권한:** `CMN_PS_DocSearch_User`(AI-002와 같은 PS)에 컨트롤러를 넣었다. `AiChangeSummary__c` 필드는 DOC-001에서 이미 만들었다.
- **라벨** 21개(ko·en_US·zh_CN).

## 4. 명세 차이·이슈·후속

| 구분 | 내용 | 조치 |
| --- | --- | --- |
| 명세 해석 | "추출 텍스트가 없는 리비전" 판정을 A단계에서는 확장자(스캔 이미지·CAD)로 한다. 스캔 PDF는 색인 단계의 추출 결과(IndexStatus·추출 길이)로 판정한다 | B단계 |
| 명세 보충 | 비교 화면을 문서 패널 버튼 + 대화상자로 정했다. 요약은 사용자가 고친 뒤 반영한다 | 보고 |
| 프로토 한계 | 비교 결과·요약은 예시 데이터(실제 파일 내용과 무관), 반영 버튼은 안내만 | R1 검토 팩에 명시 |

**화면 확인 방법:**
- **열기:** 리비전이 둘 이상인 문서가 있는 레코드(예: 샘플 테스트 레코드 문서 패널)에서 "버전 비교"를 누른다.
- **비교:** 기본 선택(바로 전 → 최신)으로 "비교"를 누르면 변경 요약·변경 목록·표 비교가 "예시 데이터" 표시와 함께 나온다.
- **비교 불가:** 이미지 파일(tif·png 등)로 올린 리비전을 고르면 "비교할 수 없습니다"가 나온다.
