## 2. 구현 내역

- **Custom Metadata:** `CMN_ChecklistProvider__mdt`(ObjectApiName, ProviderClass, IsActive). 샘플 등록은 테스트 객체 → `CMN_TestChecklistProvider`다.
- **Apex:**
  - `CMN_ChecklistProvider`: 인터페이스(load, saveAnswers, preview, raiseFollowUp).
  - `CMN_Checklist`: DTO(Sheet, Section, Question, Answer, ScorePreview, SectionScore, SaveResult, Issue, FollowUpInput). 점수 계산 로직은 없다.
  - `CMN_ChecklistDefaultProvider`: 추상 기본 구현. 후속 조치를 `CMN_ActionItem__c`로 만들고(USER_MODE, 원천 레코드 Id·질문 키), 공장 훅 `plantOf`를 둔다.
  - `CMN_ChecklistController`: Provider 찾기. 셸 공통 형식을 서버에서 다시 확인한다(편집 가능, 질문 키, 허용 점수, 배점 범위, NA 허용·사유, 선택값, 음수 결함). 점수 비공개 시트는 미리보기를 주지 않는다.
  - `CMN_TestChecklistProvider`: 샘플이자 업무 Provider의 본보기.
    - SL 자체 예시 질문 6개(답 유형 6종, 라이선스 문구 없음), 별표·안내·분담 질문.
    - 제출 규칙: 4점 이하·부적합이면 관찰 필수, 그때 후속 조치를 만들지 않으면 사유 필수.
    - 예시 점수: 비율 평균, A·B·C 등급, 별표 4점 이하면 강등.
- **LWC:**
  - `cmnChecklistRunner`:
    - 요소 목록·진행률: 태블릿·데스크톱은 왼쪽, 휴대폰은 위 선택 목록.
    - 질문 카드: 번호·별표·안내 접기, 답 유형별 입력(점수 버튼, 배점 숫자, 적합/부적합, 예/아니오, 시료·결함 A·B·C, 서술), NA·사유, 관찰 메모와 필수 안내, 후속 조치 미생성 사유, 사진, 후속 조치.
    - 데스크톱 질문 표 보기, 내 분담만, 점수 미리보기 패널.
    - 임시 저장 7일, 요소를 다 답하면 중간 저장, 전송 대기·지금 저장, 제출(NA 사유 확인, 미답 확인, 오류 질문으로 이동).
  - `cmnChecklistFollowUp`: LightningModal 대화상자(제목·내용·담당·기한·심각도).
- **화면 진입:** 앱 페이지 `CMN_Checklist`와 탭(체크리스트 수행, `c__recordId`). 내비게이션에는 넣지 않았다. 셸은 레코드 페이지와 화면 액션에도 둘 수 있다.
- **필드 추가:**
  - `CMN_ActionItem__c.SourceKey__c`(Text 80, 원천 세부 키 — 질문 키).
  - 테스트 객체 `ChecklistJson__c`.
  - UX-005 `TestChecklistEdit` 규칙(작성 중·진행 중).
- **권한·라벨:**
  - `CMN_PS_UiFramework_User`에 `CMN_ChecklistController`와 체크리스트 탭을 더했다.
  - 라벨 85개(ko·en_US·zh_CN).
- **설계 판단:**
  1. **답 형식 확인:** 허용 점수, NA 같은 답 형식은 계약 수준 규칙이라 셸과 컨트롤러가 함께 확인한다. 관찰 필수 같은 업무 규칙은 Provider만 판단한다(셸은 질문 데이터로 안내만 보인다).
  2. **중간 저장:** 요소의 보이는 질문을 다 답하면 바뀐 질문만 보낸다. 실패하면 사용자가 "지금 저장"을 누를 때까지 자동 저장을 멈춘다(UX-008과 같다).
  3. **점수 보기:** 저장하지 않은 답을 먼저 중간 저장한다. 저장이 실패하면 오래된 점수를 보이지 않으려고 미리보기를 부르지 않는다.
  4. **답 유형 상수:** 이름에 `TYPE_`를 붙였다. DTO 필드(`text`·`points`·`compliance`·`no`)와 대소문자만 다른 이름 충돌을 피하기 위해서다.

## 4. 보안·성능 점검

- [x] 후속 조치는 USER_MODE로 만들고, 담당자 To-Do·공유는 조치 항목 서비스가 맡는다.
- [x] 편집할 수 없는 상태에서는 저장과 후속 조치를 서버가 거부한다. 없는 질문 키는 요청 오류로 처리한다.
- [x] 질문지·점수 객체를 CMN에 만들지 않았다(Vol.6c 소유). 라이선스 문구를 테스트·데모에 넣지 않았다.
- [x] 사용자에게 보내는 메시지는 라벨이다. 예상하지 못한 오류 원문은 CMN_Logger에 남긴다.
