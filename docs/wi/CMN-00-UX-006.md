## 2. 구현 내역

- **원천:** `meta-src/*/grids/{GridKey}.json`(그리드 1개 = 정의 + 열 목록). 샘플은 테스트 객체 라인 `CMN_TestRecordLines`(열 10개)다.
  - metagen이 정의를 `CMN_GridDefinition__mdt`·`CMN_GridColumn__mdt` 레코드로 만든다.
  - 생성할 때 막는 것: 행 객체에 없는 필드, 최대 행 1~500 밖, 휴대폰 열 5개 이상, 코드 그룹 없는 CODE 열, 상대 폭 1~10 밖.
- **Custom Metadata:**
  - `CMN_GridDefinition__mdt`: 필드 12개.
  - `CMN_GridColumn__mdt`: 필드 12개. `Grid__c`는 Metadata Relationship이다.
  - 긴 텍스트 필드가 없어 정의 조회는 SOQL 한도에 세어지지 않는다.
- **메시지 채널:** `CMN_GridRefresh__c`(gridKey, parentId).
- **테스트 하위 객체:** `CMN_TestRecordLine__c`(개발 플랜 DEV-3). 테스트 레코드의 Master-Detail 자식이고, 입력 유형 7종을 모두 가진 필드 10개가 있다. 탭과 권한 세트는 없고, 이관 권한 세트에는 자동으로 포함된다.
- **Apex:**
  - `CMN_GridProvider`: 인터페이스(defaults, rowMeta, validate, afterSave).
  - `CMN_GridProviderBase`: 제약 없는 기본 구현. 조회하지 않은 필드를 null로 읽는 `valueOf`를 제공한다.
  - `CMN_GridRowMeta`: blockDelete, lock, warn.
  - `CMN_GridValidation`: 행 순번·셀 필드·그리드 오류.
  - `CMN_GridSelector`: 정의는 SYSTEM_MODE, 행·참조는 USER_MODE로 조회한다. UserRecordAccess로 편집 권한을 확인한다.
  - `CMN_GridService`: load, save, resolveLookups.
  - `CMN_GridController`: `@AuraEnabled` 3개. 예외를 라벨 문구로 한곳에서 바꾼다.
  - `CMN_TestRecordLineGridProvider`: 샘플 Provider이자 업무 Provider의 본보기.
    - 완료 행은 삭제할 수 없고 일정·수량이 잠긴다.
    - 기한이 지난 미완료 행에는 경고를 단다.
    - 종료일이 시작일보다 빠르거나 수량이 음수이면 오류다.
- **LWC:**
  - `cmnEditableGrid`: 본체. 툴바, 초안, 붙여넣기 적용, 검증, 저장, 일정·휴대폰 보기, LMS 구독을 맡는다.
  - `cmnGridDatatable`: `lightning-datatable`을 확장해 커스텀 타입 4개(선택 목록·참조·코드·행 상태)를 더한다.
  - `cmnGridCellLabel`: 셀 표시.
  - `cmnGridLookupInput`: `lightning-record-picker` 편집 셀.
  - `cmnGridCodeInput`: `cmnCodePicker` 편집 셀.
  - `cmnGridPasteDialog`: LightningModal로 만든 붙여넣기 대화상자.
  - `cmnGridPasteParser`: 순수 함수 모듈. 탭 구분·따옴표 셀, 로캘 날짜·숫자, 선택 목록 라벨, 참·거짓 낱말을 해석한다.
  - `cmnGridSchedule`: CSS 막대.
  - `cmnDraftStore`: localStorage 초안. 14일 뒤 만료되고, UX-008·009도 쓴다.
- **권한·라벨:**
  - `CMN_PS_UiFramework_User`에 `CMN_GridController`를 더했다.
  - 라벨 81개(ko·en_US·zh_CN).
- **UX-005 확장:**
  - COMPONENT 규칙에 `mode: EDIT`를 더했다. 화면 가시성 없이 편집 가능 여부만 판정한다(그리드 EditRuleKey).
  - metagen(Mode__c), `ui-rule-sync.py`(동기화 제외·문서·검증)에 반영했다.
  - 테스트 객체에 `TestLinesEdit` 규칙(작성 중·진행 중)을 더했다.
- **샘플 배치:**
  - 테스트 레코드 페이지(데스크톱·휴대폰) "현재 단계" 탭에 그리드(식별자 `TestLinesGrid`)를 두었다.
  - 레코드 페이지 정의에도 같은 컴포넌트를 더했다.
- **Jest 기반:** `jest-mocks/lightning/modal`을 더했다. sfdx-lwc-jest에 LightningModal 스텁이 없어서이고, UX-008·009도 쓴다.
- **설계 판단:**
  1. **clientVersion:** 행 수 + 최대 LastModifiedDate + 보이는 열 값 해시(SHA-256 앞 16자)다. LastModifiedDate가 초 단위라 같은 초 안의 저장을 놓쳤다. 테스트에서 발견해 해시를 더했다.
  2. **Provider 행 오류 위치:** validate가 받은 rows 목록의 순번으로 단다. 새 행에는 Id가 없어 Provider가 화면 행 키를 알 수 없기 때문이다. 범위 밖 순번은 그리드 오류로 바꾼다.
  3. **수정 행 처리:** Provider에는 현재 값에 변경을 합친 전체 행을 준다(시작·종료 비교 등). DML에는 바뀐 필드만 담은 별도 레코드를 쓴다. 조회한 읽기 전용 필드가 USER_MODE DML에 섞이지 않게 하기 위해서다.
  4. **새 행 값 순서:** Provider 기본값(열이 아닌 필드 포함) → 부모 → 순서 필드(마지막 + 1) → 화면 값.
  5. **삭제 버튼:** 표시를 토글한다(다시 누르면 되돌림). 새 행은 바로 뺀다. 삭제할 행에 대한 수정은 버린다.
  6. **응답 방식:** 업무 오류(편집 불가, 충돌, 행 오류)는 저장 결과로 돌려주고, 요청·설정·권한 오류는 예외(라벨 문구)로 돌려준다.
  7. **입력 유형:** InputType 지정은 CODE만 의미가 있다. 그 밖의 지정은 필드 타입을 따른다. 날짜시간·다중 선택은 읽기 전용(DISPLAY) 열이다.

## 4. 보안·성능 점검

- [x] 행·참조 조회는 USER_MODE 동적 SOQL이다. 식별자는 describe로 검증하고 escapeSingleQuotes로 감싸며, 값은 바인드한다. upsert·delete는 AccessLevel.USER_MODE로 한다. `without sharing`은 없다.
- [x] 읽을 수 없는 필드의 열은 응답에서 뺀다. 화면이 보낸 열이 편집 열이 아니면 거부한다(보이지 않는 열 쓰기 차단).
- [x] 저장하는 행이 이 부모·고정 필터의 현재 행인지 서버가 다시 확인한다(다른 부모의 행 Id 거부).
- [x] 편집 가능 여부(부모 권한 + 편집 규칙)와 행 메타(삭제 불가, 잠긴 셀)를 서버가 다시 판정한다.
- [x] 사용자에게 보내는 메시지는 라벨이다. 검증 규칙·addError 문구만 그대로 보내고, 그 밖의 DML 오류 원문은 CMN_Logger에 남긴다.
- [x] 루프 안 DML은 없다. 참조 확인 SOQL은 Lookup·CODE 열마다 1회로, 열 수에 묶이고 행 수와 무관하다.
- [x] 브라우저 초안은 사용자별 키로 저장하고 14일 뒤 만료된다. 업무 데이터 원본이 아니다.
