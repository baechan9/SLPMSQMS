## 2. 구현 내역

- **Custom Metadata:** `CMN_FieldEntryProvider__mdt`(ObjectApiName, ProviderClass, IsActive). 샘플 등록은 테스트 객체 → `CMN_TestFieldEntryProvider`다.
- **Apex:**
  - `CMN_FieldEntryProvider`: 인터페이스(load, save, validateScan).
  - `CMN_FieldEntry`: DTO(Sheet, Header, HeaderField, Item, Value, SaveResult, Issue)와 공용 규격 비교(judgeValue, judgeItem, overall — HALF_UP 반올림, 경계 포함, 한쪽 규격).
  - `CMN_FieldEntryController`:
    - Provider 찾기(Type.forName).
    - 셸 공통 규칙 재확인: 편집 가능, 값의 항목·시료 범위, 최종 저장의 NG 사진·측정기 번호.
    - 헤더 보조 정보 라벨 채우기, 스캔 오류 라벨을 문구로 바꾸기.
  - `CMN_TestFieldEntryProvider`: 샘플이자 업무 Provider의 본보기.
    - 항목 5개: 계량형 양쪽 규격 CC + 측정기 필수, 계량형 한쪽 규격 SC, 계수형 NG 사진 필수, 외관, 서술.
    - 값은 레코드 `EntryJson__c`에 JSON 묶음으로 저장한다.
    - 편집 가능 여부는 UX-005 `TestFieldEntryEdit` 규칙으로 정한다.
- **LWC:**
  - `cmnFieldEntryShell`:
    - 순차 모드: 큰 숫자 입력(`inputmode="decimal"`), OK/NG 큰 버튼, Enter로 다음.
    - 표 모드: 행 = 항목, 열 = 시료, 세로 붙여넣기.
    - 진행률, 미입력만 보기, 특별특성 기호, 기준 문서 열기.
    - 로트·측정기 스캔(`cmnBarcodeScanner`), NG 사진(`cmnPhotoCapture`).
    - 임시 저장(7일), 항목을 다 채우면 중간 저장, 전송 대기·지금 저장, 판정 확정(미입력 확인, 서버 차이 강조, 후속 안내).
  - `cmnFieldEntryJudge`: 미리보기 규격 비교(서버와 같은 규칙), OK/NG 낱말.
- **화면 진입:**
  - 앱 페이지 `CMN_FieldEntry`와 탭(현장 입력, 상태 매개변수 `c__recordId`). 내비게이션에는 넣지 않았다.
  - 셸은 레코드 페이지와 화면 액션(`lightning__RecordAction`)에도 둘 수 있다.
- **공통 부품 보강(하위 호환):**
  - `cmnDraftStore`: 초안별 보관 기간(기본 14일, 현장 입력 7일).
  - `cmnPhotoCapture`: `uploaded` 이벤트에 `documentIds`를 더했다(UX-001, 기존 `count` 유지).
- **테스트 객체:** `EntryJson__c`(긴 텍스트), `EntryResult__c`. UX-005 `TestFieldEntryEdit` 규칙(작성 중·진행 중)을 더했다.
- **권한·라벨:**
  - `CMN_PS_UiFramework_User`에 `CMN_FieldEntryController`와 현장 입력 탭을 더했다.
  - 라벨 62개(ko·en_US·zh_CN).
- **설계 판단:**
  1. **모드 기본값:** 데스크톱은 Provider의 `defaultMode`(기본 표), 휴대폰·태블릿은 항상 순차로 연다.
  2. **중간 저장:** 항목 하나가 판정 가능해지면(입력 중이 아니게 되면) 보낸다. 바뀐 항목만 보내고, 보내는 동안 다시 바뀐 항목은 전송 대기로 남긴다.
  3. **자동 저장 멈춤:** 저장이 한 번 실패하면 사용자가 "지금 저장"을 누를 때까지 자동 중간 저장을 멈춘다(자동 재전송 0회).
  4. **측정기 번호:** 항목 단위로 확인하고, 저장할 때 그 항목의 모든 값에 붙인다.
  5. **서버 재확인:** 저장할 때마다 Provider `load`를 다시 불러 편집 가능 여부와 값 범위를 확인한다. 화면을 거치지 않은 호출을 막기 위해서다.

## 4. 보안·성능 점검

- [x] Provider 등록은 메타데이터로 찾고, 클래스 이름 형식과 인터페이스 구현을 확인한다. 미등록·오류는 같은 안내 문구로 보이고, 원인은 로그에 남긴다.

- [x] 입력값은 시트 항목·시료 범위와 OK/NG 값만 받는다. 최대 5,000칸이다.

- [x] 사용자에게 보내는 메시지는 라벨이다. 예상하지 못한 오류 원문은 CMN_Logger에 남긴다.
