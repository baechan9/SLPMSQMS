## 2. 구현 내역

- 필드: `User.LanguageOverride__c`, 마스터 11개(법인·공장·라인·공정·부서·제품군·품번·차종·코드 그룹·코드·품질 특성)에 `NameEn__c`·`NameZh__c`·`DisplayName__c`(BR-3 수식) — 생성기 옵션 `i18nName`으로 붙여 각 마스터 PS에 자동 반영.
- Apex: `CMN_LanguageService`(포털 언어 → LanguageLocaleKey, 포털 언어 적용·직접 지정·포털 따르기), `CMN_SamlJitHandler`(updateUser만, createUser는 거부), `CMN_LanguageController`(스위처 상태·저장). `CMN_CodePickerController`의 표시명 규칙을 BR-3과 같게 맞춤(pl·es·pt → 영문).
- LWC: `cmnLanguageSwitcher`(유틸리티 바), 유틸리티 바 페이지 `SL_UtilityBar`를 SL QMS·SL PMS·SL Admin 앱에 연결.
- 권한·라벨: `CMN_PS_Language_User`(사내 PSG 14개), 라벨 13개(언어 이름 6개는 각 언어로 쓴 이름이라 번역이 같다).
- 도구: 한글 리터럴 검사 스크립트(CI·점검 스크립트), 생성기 번역 누락 검사(객체·필드·선택 목록 값·검증 규칙·레코드타입·라벨의 ko·en_US·zh_CN — BR-6 완료 조건을 생성 단계에서 강제).
- 핵심 설계 판단:
  1. **표시명은 수식, 피커는 같은 규칙의 Apex**: 목록·레코드 화면은 `DisplayName__c`, 코드 피커는 서버에서 같은 규칙으로 이름을 고른다(테스트로 두 결과가 같은지 확인).
  2. **포털 언어 vs 직접 지정**: 스위처가 언어를 고르면 `LanguageOverride__c = true`로 저장하고 SSO JIT는 그 사용자의 언어를 건드리지 않는다. "포털 언어 따르기"는 직접 지정만 풀고 다음 로그인부터 포털 언어를 쓴다.
  3. **JIT는 사용자를 만들지 않는다**: 등록되지 않은 사용자의 SSO 로그인은 라벨 문구로 거부(사용자 생성은 HR 연계만).
  4. **자기 언어 저장은 시스템 모드**: 사용자 FLS로는 직접 지정 필드가 읽기라, 서비스가 자기 사용자 레코드의 언어·직접 지정만 바꾼다.
