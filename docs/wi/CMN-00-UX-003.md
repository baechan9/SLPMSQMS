## 2. 구현 내역

- 메타데이터
  - `CMN_StatusFlow__mdt`(ObjectApiName·StatusField), `CMN_StatusStep__mdt`(StatusFlow = 메타데이터 관계, Value·Sequence·LabelKey·IsTerminal). 레코드: 테스트 대상 객체(4단계, 라벨 키), 결재 요청(5단계, 선택 목록 라벨).
  - `CMN_Comment__c`(ParentRecordId·ParentObject·Body·MentionedUserIds·IsEdited, OWD Private, Owner = 작성자, 읽기 전용 레이아웃, 번역).
  - PS `CMN_PS_Comment_User`(코멘트 CRUD·컨트롤러 2개 접근, 사내 페르소나 PSG 전체).
  - 라벨 29개(상태 4종, 진행바 2, 코멘트 화면·오류, 멘션 알림 제목/본문, 공통 로딩). NTF 규칙 `CMN_COMMENT_MENTION`. CMN 설정 `CMN_COMMENT_EDIT_HOURS`(24), `CMN_COMMENT_MAX_MENTIONS`(20).
- Apex: `CMN_StatusPathController`(+ `CMN_StatusFlowSelector`), `CMN_CommentController`·`CMN_CommentService`·`CMN_CommentSelector`(읽기만 without sharing, 사유 주석)·`CMN_CommentTriggerHandler` + 트리거.
- LWC: `cmnStatusPath`(속성 recordId·objectApiName, `lightning-progress-indicator` path), `cmnCommentTimeline`(속성 recordId). 둘 다 레코드 페이지, 데스크톱·모바일.
- 생성기: `MetadataRelationship` 필드 유형 지원(docs/dev/metadata-generator.md 반영).
- 핵심 설계 판단
  1. **상태 값은 LDS, 흐름 정의는 Apex**: 정의는 캐시 가능한 설정이라 Apex(`cacheable`)로, 현재 값은 `getRecord`(단건 LDS)로 읽어 업무 버튼·결재 콜백으로 상태가 바뀌면 진행바가 바로 바뀐다.
  2. **종료 단계 표시**: 종료가 아닌 단계 전부 + 종료 칸 하나. 현재가 종료 상태면 그 상태, 아니면 순서가 가장 앞선 종료(정상 완료). 정상 완료가 아닌 종료(반려·취소)는 오류 표시. 새 필드 없이 Sequence로 정한다.
  3. **코멘트 공유 = 부모 접근**: 코멘트는 Private(작성자 소유)로 두고, 조회는 `UserRecordAccess.HasReadAccess`를 확인한 부모의 코멘트만 시스템 모드로 읽는다. 쓰기도 트리거가 부모 읽기 권한을 확인한다. 보고서·API로 다른 공장 코멘트가 새지 않는다.
  4. **규칙은 트리거에서 강제**: 작성자 본인·24시간·부모 변경 불가·본문 필수·멘션 정리를 트리거가 하므로 화면·API·Flow 어디서 저장해도 같다. 판정은 저장된 작성자·작성 시각을 다시 읽어 한다(테스트의 `Test.setCreatedDate`가 `Trigger.old`에는 반영되지 않음을 확인).
  5. **멘션 입력**: 표준 `lightning-record-picker`(활성 사용자)로 고르고 이름은 단건 LDS로 읽어 칩으로 보인다. 본문 텍스트 파싱으로 사용자를 찾지 않는다(동명이인·다국어 이름).
