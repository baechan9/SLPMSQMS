## 2. 구현 내역

- **원천:** `meta-src/*/ui-rules/{객체}.json`(섹션 정의 + 규칙 표). 샘플은 테스트 객체 `CMN_TestRecord__c`다.

  | 대상 | 종류 | DRAFT | IN_PROGRESS | DONE | CANCELLED |
  | --- | --- | --- | --- | --- | --- |
  | Basic(기본 정보) | SECTION | 편집 | 읽기 | 읽기 | 읽기 |
  | Schedule(일정) | SECTION | 편집 | 편집 | 읽기 | 읽기 |
  | Edit(수정) | ACTION | 표시 | 표시 | 숨김 | 숨김 |
  | Delete(삭제) | ACTION | 표시 | 숨김 | 숨김 | 숨김 |
  | cmnDueIndicator(기한 표시) | COMPONENT | 표시 | 표시 | 숨김 | 숨김 |

- **Custom Metadata:**
  - `CMN_UiRule__mdt`(필드 11개)와 `CMN_UiSection__mdt`(필드 4개).
  - 레코드는 `metagen.py`가 ui-rules 정의로 만든다(규칙 5, 섹션 2).
- **FlexiPage 동기화** `scripts/dev/ui-rule-sync.py`:
  - SECTION: 편집 섹션 `{Key}EditSection`은 허용 조건일 때 보인다. 읽기 섹션 `{Key}ReadOnlySection`은 없으면 만들고(같은 필드, 읽기 전용) 부정 조건일 때 보인다.
  - ACTION: 하이라이트 패널을 Dynamic Actions로 바꾸고 규칙이 있는 버튼만 조건과 함께 넣는다. 휴대폰 페이지는 모바일 Dynamic Actions를 켠다.
  - COMPONENT: 식별자가 키인 컴포넌트에 가시성 규칙을 단다.
  - 조건식: 규칙 행들의 OR. 행 하나 = 상태 ∈ 값(OR) AND 권한 AND 레코드 타입(OR) AND 폼 팩터 AND 추가 조건.
  - 조건 10개를 넘으면 멈춘다.
  - 모드: `--check`(CI: FlexiPage 불일치, 없는 Custom Permission, 정의 밖 상태값, 섹션 정의 없는 규칙)와 `--doc`(위 매트릭스 md).
- **Apex:**
  - `CMN_UiRuleService`:
    - `canExecute`, `assertCanExecute`(라벨 `CMN_UiRule_ActionNotAllowed`).
    - `lockedFieldViolations`: 이전 상태 기준, 바뀐 필드만 본다.
    - `addLockErrors`: 필드 라벨을 넣은 행 오류(`CMN_UiRule_FieldLocked`).
    - `runAsService(Callable)`: 호출 안에서만 우회한다.
    - Custom Permission 판정을 캐시한다.
  - `CMN_UiRuleSelector`: 객체별 정적 캐시. 긴 텍스트가 없어 SOQL 0회다.
  - 테스트 객체 트리거 핸들러에 before update 잠금을 더했다(테스트 스위치).
- **CI:** `ui-rule-sync.py --check`를 `ci.yml`과 `wi-check.sh`에 넣었다.
- **라벨(ko·en_US·zh_CN):** 2개.
- **설계 판단:**
  - (1) 서버 판정은 화면과 같은 규칙 데이터로 하고, 폼 팩터 조건은 서버에서 보지 않는다.
  - (2) 레코드를 사용자 권한으로 읽을 수 없으면 거부한다.
  - (3) 추가 조건의 빈 값은 빈 문자열로 비교한다.
  - (4) 폼 팩터 LARGE = 휴대폰이 아닌 것(데스크톱·태블릿).
