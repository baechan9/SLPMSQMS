## 2. 구현 내역

- **객체** `CMN_AiRecommendation__c`(비공개, 공장 공유 사유 `CMN_Plant__c`):
  - 명세 필드 전부: UseCase 11종, SourceRecordId(외부 ID = 조회 인덱스)·SourceObject, Rank, ContentJson·Rationale·SourceRefs, Score, PromptVersion·ModelInfo, Status, ExcludeReason(코드 그룹 필터), DecidedBy·DecidedAt, FinalOutcomeJson, IsHit.
  - 더한 필드: FinalizedAt(Vol.8 요청), Plant, SourceLink(대상 레코드 바로 가기 수식).
  - 결정 관련 필드는 서비스 전용(화면·권한 셋 읽기 전용)이다.
  - 검증 규칙 `CMN_AiRecommendation_ExcludeReason`(제외면 사유 필수).
  - 목록 "제안 중"·"제외됨"·"확정 평가됨"·"전체", 읽기 전용 레이아웃, 콤팩트 레이아웃.
  - 공유 설정 `CMN_SharingConfig__mdt.CMN_AiRecommendation`(공장 필드 Plant__c).
- **Apex:**
  - `CMN_AiHitRule`: 적중 규칙 인터페이스. 업무 WI가 구현한다.
  - `CMN_AiRecommendationService`:
    - record: 검증, 이전 PROPOSED 만료, 원천 공장 조회, 제목.
    - decide: 편집 접근 확인, 닫힌 추천 거부, 제외 사유는 코드 Id 또는 값.
    - finalize: 만료 제외 전부 평가, 다시 부르면 덮어쓴다.
    - validUseCases, editableIds.
  - `CMN_AiRecommendationController`: getRecommendations(만료 제외, 순위순, 50건, 카드 DTO)와 decide.
  - 트리거 `CMN_AiRecommendationTrigger`와 핸들러: 제목 보정과 공장 공유(기반 클래스).
- **LWC:**
  - `cmnAiRecommendationList`:
    - 레일 패널 계약(recordId·objectApiName·config·variant)과 App Builder 속성 useCase.
    - 순위·상태·신뢰·적중 배지, 문장·이름-값, 근거 펼치기, 출처 링크, 결정자·시각·제외 사유.
    - 채택·수정 채택·제외 버튼(현재 결정은 눌린 상태), 레일 3건·더 보기, railbadge.
    - 결정 알림: DOM 이벤트와 메시지 채널.
    - RefreshEvent 재조회, UseCase 렌더러 동적 로드, "AI 추천은 참고용" 안내.
  - `cmnAiExcludeDialog`: 제외 사유 코드 선택(`cmnCodePicker`, AI_EXCLUDE_REASON) 필수.
- **메시지 채널** `CMN_AiRecommendation`: recordId, recommendationId, useCase, status, rank, contentJson.
- **화면 연결:**
  - 결정 지원 레일 `DEFAULT_AI` 패널을 켰다(UX-004 "AI-004 배포 전 비활성"). 모든 업무 레코드 레일에서 AI 패널이 기본 펼침이다.
  - 메뉴 허브 `QMS_08_AIQ_RECORD`를 객체 목록에 연결했다. 탭은 AI 추천이다.
- **권한 셋:**
  - `CMN_PS_AiRecommendation_User`: 읽기·편집. 편집은 레코드 편집 접근 판정용이고 만들기·삭제는 없다. 컨트롤러와 탭도 준다. 사내 PSG 14개에 넣었다.
  - `CMN_PS_AiRecommendation_Admin`: 모두 보기와 탭. SystemAdmin과 QualityAdmin에 넣었다.
- **개발 스크립트** `scripts/apex/seed-ai-recommendations.apex`: Scratch 샘플 테스트 레코드에 원인 추천 3건을 기록한다(예시 문구).

## 4. 보안·성능 점검

- [x] 사람 확정 원칙: 컴포넌트와 서비스는 업무 필드를 쓰지 않는다. 채택은 기록과 알림만 하고 반영은 업무 화면이 한다(BR-3).
- [x] 목록은 사용자 권한(USER_MODE)과 공장 공유로 읽는다. 결정은 추천 레코드 편집 접근(UserRecordAccess)이 있어야 한다.
- [x] 결정 필드는 서비스 전용이라 FLS를 건너뛰는 시스템 모드로 저장한다. 공유는 클래스의 with sharing을 따른다(공유 예외 없음).
- [x] 동적 SOQL은 바인드만 쓴다. 원천 객체 이름은 Id의 describe에서 가져온다.
- [x] 사용자 메시지는 라벨이다. 예상하지 못한 오류 원문은 CMN_Logger에 남긴다.
- [x] 출처 링크는 올바른 레코드 Id만 만든다. 렌더러 이름은 `c/이름` 형식만 허용한다.
